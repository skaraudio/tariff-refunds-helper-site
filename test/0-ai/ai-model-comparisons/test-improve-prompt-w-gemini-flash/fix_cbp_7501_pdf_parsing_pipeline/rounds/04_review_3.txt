### Phase 2: PDF Parser Robustness & Telemetry Implementation
1. Refactor `lib/pdf/parse-entry-summary.mjs`:
   - Implement tokenization logic capable of separating Form 7501 column blocks (Box 27 Line No, Box 28 HTS No, Box 29 Rate, Box 30 Entered Value, Box 32 Duty Amount) when whitespace delimiters are missing from `pdf-parse` text streams.
   - Refine HTS pattern matching to isolate `^9903\.01\.\d{2}$` (and 8-digit variants `990301xx`) from surrounding alphanumeric tokens.
   - Extract per-line details: `entryLineNumber`, `htsNumber`, `dutyRate`, `enteredValue`, and `dutyAmount`.
   - Set `isEligible: true` if and only if at least one valid `9903.01.xx` line item with a non-zero duty refund is identified.
   - Calculate `totalRefundAmount` as the exact arithmetic sum of duty amounts paid on eligible line items.
2. Implement parse telemetry on the returned result object:
   - `parseConfidence`: Float between `0.00` and `1.00`, calculated as `(0.25 * header_valid) + (0.45 * line_checksum_match) + (0.30 * block_match_ratio)`, where checksum reconciliation compares summed line duties against Box 39 / grand total if present.
   - `parseQuality`: String enum:
     - `'high'`: `parseConfidence >= 0.85` with all identified line items cleanly parsed.
     - `'medium'`: `parseConfidence` between `0.60` and `0.84` with IEEPA lines extracted.
     - `'low'`: `parseConfidence` between `0.20` and `0.59`, severe column concatenation or line checksum mismatch.
     - `'failed'`: `parseConfidence < 0.20` or unreadable document structure.
   - `parseWarnings`: Array of error/warning string codes (e.g. `'DUTY_TOTAL_MISMATCH'`, `'CONCATENATED_TOKENS_RECOVERED'`, `'MISSING_BOX_39_TOTAL'`).
3. Dispatch `test-engineer` to author and execute `.claude/temp/workspace/benchmark-parser.mjs` against `.claude/temp/example-entry-summaries/`.
4. **GATE 2**: Benchmark must demonstrate zero false negatives (100% of samples with `9903.01.xx` in raw text parsed as `isEligible: true`) and exact refund arithmetic against `baseline-parser-audit.json` before moving to Phase 3.
